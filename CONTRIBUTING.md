# Contribution Guidelines

Thank you for considering contributing to the Awesome MotiveWave Studies list! Please follow these guidelines to ensure your contributions are accepted.

## How to Contribute

1. **Fork the repository** and create a new branch for your contribution.
2. **Add your study or resource** to the appropriate section in README.md.
3. **Follow the formatting guidelines** outlined below.
4. **Submit a pull request** with a clear description of your addition.

## Quality Standards

To be added to this list, studies and resources must meet the following criteria:

### For Studies

- **Functional**: The study must be working and tested with the latest MotiveWave version.
- **Documented**: Include clear documentation explaining what the study does and how to use it.
- **Original or Valuable**: Provide unique functionality or significant improvements over existing studies.
- **Well-Coded**: Follow Java best practices and MotiveWave SDK guidelines.
- **Open Source**: The code should be publicly accessible (preferably on GitHub).

### For Resources

- **Relevant**: Must be directly related to MotiveWave study development.
- **Quality**: High-quality content that provides value to the community.
- **Accessible**: Available online and not behind paywalls (exceptions for official documentation).
- **Current**: Up-to-date and maintained content.

## Formatting Guidelines

### Studies

Use the following format when adding a study:

```markdown
- [Study Name](https://github.com/username/repository) - Brief description of what the study does.
```

**Example:**
```markdown
- [Advanced RSI](https://github.com/johndoe/advanced-rsi) - Enhanced RSI indicator with multiple timeframe support and divergence detection.
```

### Resources

Use the following format when adding a resource:

```markdown
- [Resource Name](https://example.com) - Brief description of the resource.
```

**Example:**
```markdown
- [MotiveWave Study Patterns](https://example.com/patterns) - Common design patterns for MotiveWave studies.
```

## Alphabetical Ordering

Within each category, entries should be ordered alphabetically by the study/resource name (case-insensitive).

## Pull Request Guidelines

When submitting a pull request:

1. **One addition per PR**: Submit separate pull requests for multiple additions.
2. **Clear title**: Use a descriptive title like "Add [Study Name] indicator" or "Add [Resource Name] tutorial".
3. **Description**: Explain what you're adding and why it belongs in the list.
4. **Check for duplicates**: Make sure the study/resource isn't already listed.
5. **Test links**: Verify all URLs are working before submitting.

## Categories

If you believe a new category is needed:

1. **Propose the category** in an issue first to discuss with maintainers.
2. **Provide at least 3 items** that would fit in the new category.
3. **Update the table of contents** accordingly.

## Removing Items

If you find a broken link or outdated resource:

1. **Create an issue** to notify maintainers.
2. **Submit a PR** removing the item with an explanation.

## Code of Conduct

This project follows the [Contributor Covenant Code of Conduct](https://www.contributor-covenant.org/version/2/0/code_of_conduct/). By participating, you are expected to uphold this code.

### Expected Behavior

- Be respectful and inclusive
- Accept constructive criticism gracefully
- Focus on what is best for the community
- Show empathy towards other community members

### Unacceptable Behavior

- Harassment, discrimination, or trolling
- Publishing others' private information
- Spam or self-promotion without value
- Any conduct that would be inappropriate in a professional setting

## Questions?

If you have questions about contributing, feel free to:

- Open an issue for discussion
- Reach out to maintainers
- Ask in the MotiveWave community forums

Thank you for helping make this list awesome!
